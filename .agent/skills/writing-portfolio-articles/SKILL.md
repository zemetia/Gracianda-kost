# Writing Portfolio Articles

## Quick Start
"Create a professional business article for the new 'Dynamic Dashboard' page. Focus on how it solves real-time data visualization for the client."

## When to Use
- When preparing a project for a portfolio or case study.
- When the user asks to "document" a feature or page for a business/marketing audience.
- When turning technical implementation details into persuasive business content.

## Workflow
1. **Identify Scope**: Determine if the article is about a single feature, a specific page, or a collection of major pages and features.
2. **Context Retrieval**: Scan the relevant files (UI components, API routes, logic) to understand the "How".
3. **Value Analysis**: Identify the "Why". What business problem does this solve? How does it improve user experience?
4. **Drafting**: Use the **Premium Portfolio Template** (see below).
5. **Tone Check**: Ensure the language is executive-level, professional, and impactful.

## Premium Portfolio Template
Use this structure for every article:

### 1. The Hook (Headline)
- A bold, benefit-driven title. (e.g., "Revolutionizing Fleet Management: The Real-Time Logistics Engine")

### 2. Executive Summary
- A 2-3 sentence overview of the project/feature scope and its ultimate goal.

### 3. The Challenge (Problem Statement)
- Define the friction point or business gap that existed before this implementation.

### 4. The Architectural Solution
- Describe the implementation in "Business-Technical" terms. (e.g., "Leveraging Next.js Server Components for instantaneous state hydration...")
- Focus on *choice* (Why this tech? Why this design?).

### 5. Feature Deep-Dive (The "Magic")
- Break down the core functionalities (as requested by the user).
- Use bullet points with "Feature-to-Benefit" mapping.

### 6. The User Experience (Visual/Interactive Impact)
- Describe the aesthetic and flow. (Mention animations, responsiveness, and "Premium" feel).

### 7. Results & Impact
- Summarize the value added (Efficiency, Scalability, or Brand Perception).

## Instructions
- **Language**: Strictly Professional English (US/UK). Avoid slang or overly casual transitions.
- **Perspective**: Third-person professional or first-person plural (e.g., "The system enables..." or "We implemented...").
- **Depth**: Adjust depth based on user request. If "Major Feature only," focus on high-level impact. If "Page," include UI/UX details.
